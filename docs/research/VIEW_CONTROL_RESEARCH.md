# 智能视角平滑控制与真实多模态输入融合调研方案

> 首版应先解决时间同步、状态估计和受约束平滑三个可验证问题，再讨论轨迹风格；所有实验只使用真实触控与真实传感器数据，不生成或注入伪造输入，也不以规避检测为目标。

交互式三维系统常同时接收触控、陀螺仪和视觉观测。直接插值虽然容易实现，却会把采样抖动、时钟偏差和目标跳变一并传入控制端；堆叠随机贝塞尔控制点、随机过冲和人工噪声又会降低可复现性，并不能证明动作更自然。

因此，本调研把问题拆成三层：先把不同来源的数据对齐为可信状态，再把用户意图与外部观测分开估计，最后用连续且有界的运动模型生成视角建议。研究成果面向相机稳定、无障碍辅助、遥操作和用户主动选择后的视角跟随。当前仓库中的目标检测结果只作为观测和离线评估输入，不触发自动触控或传感器注入。

## 1. 先建立可信状态，融合才有意义

### 1.1 统一时间与坐标

每条输入记录 `eventTimeNs`、`receiveTimeNs`、来源、精度状态和会话 ID。Android `SensorEvent.timestamp` 与 `SystemClock.elapsedRealtimeNanos()` 使用同一时间基准，可直接作为 IMU 事件时刻；触控、画面采集和推理结果也应转换到同一单调时钟域。

融合前固定四类坐标系及转换方向：屏幕像素、归一化视口、设备坐标和世界/相机坐标。旋转、横竖屏切换或显示尺寸变化时递增 `transformGeneration`，丢弃旧 generation 的在途数据，避免把旧姿态应用到新画面。

时间对齐采用短窗口重采样，不用“最新值覆盖最新值”：

1. 以控制 tick 的时间 `t` 为查询点；
2. 触控位移在相邻事件间分段累计；
3. 陀螺仪在事件时间上积分为四元数增量；
4. 视觉观测按采集时间外推，并携带帧龄和置信度；
5. 超过最大帧龄的数据降权或拒绝，不静默参与融合。

### 1.2 先标定，再估计

每台设备建立只读标定档案，至少包含触控像素到角位移的比例、陀螺仪零偏、轴向映射、屏幕旋转和传感器采样率。标定结果带设备指纹、ROM、应用版本和时间戳；配置不匹配时回到未标定状态。

姿态估计首轮对比两条路线：

- 互补滤波作为低复杂度基线，用陀螺仪保持短时响应，用重力方向约束 pitch/roll 漂移；无可靠磁场参考时不声称长期 yaw 无漂移。
- Madgwick 或等价四元数滤波作为候选，比较其收敛、CPU 开销和对设备振动的敏感性。

滤波器只处理测量不确定性。真实静止段用于估计噪声谱和零偏，不向数据中人工叠加 8–12 Hz 正弦波、高斯噪声或轴间随机耦合。

## 2. 把用户意图与辅助观测分开融合

### 2.1 用状态机代替单一角度阈值

单个 `thetaThreshold` 容易在边界附近来回切换。控制器采用带滞回和最短驻留时间的五态模型：

```text
IDLE ──真实用户输入──> ACQUIRE ──观测稳定──> TRACK ──误差收敛──> HOLD
  ^                         │                    │               │
  └────────停止/取消────────┴────观测失效─────────┴────超时──────> LOST
```

- `ACQUIRE`：以用户触控为主，快速建立方向和速度意图。
- `TRACK`：融合真实触控、真实 IMU 与有效视觉观测，权重随各通道新鲜度和不确定度连续变化。
- `HOLD`：降低辅助增益并保留用户输入，死区使用进入/退出两个阈值避免抖振。
- `LOST`：视觉观测过期或跳变时平滑降为纯用户控制，不延用最后目标。

任何新触控手势都具有最高优先级，可立即减弱或取消辅助。视觉结果只在用户已选择的目标或 ROI 内提供跟随建议；检测器自行发现的对象不获得控制权。

### 2.2 权重由置信度决定，而不是随机决定

在统一角速度空间中融合：

$$
\boldsymbol{\omega}_{cmd}=
w_t\boldsymbol{\omega}_{touch}+
w_g\boldsymbol{\omega}_{gyro}+
w_v\boldsymbol{\omega}_{assist},
\quad w_t+w_g+w_v=1
$$

权重由事件帧龄、传感器精度、视觉置信度、当前状态和用户覆盖量计算并做连续限速。首版采用可解释规则建立基线，收集回放数据后再评估卡尔曼滤波或学习型门控；不在没有协方差和真值的情况下先引入复杂模型。

### 2.3 轨迹以最小加加速度和物理约束为基线

点到点运动采用五次多项式：

$$
p(s)=p_0+(p_1-p_0)(10s^3-15s^4+6s^5),\quad s\in[0,1]
$$

它使起止速度和加速度连续归零，便于约束峰值角速度、角加速度和加加速度。持续跟踪则使用临界阻尼二阶系统或模型预测控制，逐 tick 限制 `omega`、`alpha` 和 jerk。上限由设备与用户实测分位数标定，不预设 `250°/s` 为通用人体极限。

Fitts 定律用于预测“移动距离和目标宽度如何影响完成时间”，作为任务难度分层与实验分析工具；它不直接定义速度曲线。贝塞尔曲线可以作为带障碍路径的几何候选，但随机控制点、固定概率过冲和随机目标落点不进入默认控制链路。

## 3. 用滤波、滞回和降级消除抖动

首版比较 One Euro Filter 与常系数低通。One Euro Filter 可在低速时加强平滑、高速时降低延迟，适合处理交互输入的“抖动—时延”权衡。每个通道只在一个明确层级滤波，避免传感器、状态估计和输出端重复低通造成不可解释的滞后。

控制端采用椭圆死区与滞回：进入 `HOLD` 的阈值小于退出阈值；死区大小随测量协方差放大，而非固定为某个屏幕像素值。观测失效、时间倒退、坐标 generation 变化或计算超时时，输出按有限斜率衰减到用户原始输入，并记录降级原因。

## 4. 评估同时回答“稳不稳、跟不跟手、是否可复现”

### 4.1 数据与对照

建立三类版本化数据：台架固定设备数据、用户任务数据、故障注入数据。故障注入只发生在离线回放层，用于测试丢包、延迟、时间倒退、轴映射错误和视觉跳变；不得伪装成真实传感器事件送入其他应用。

每次实验比较四个配置：原始输入、固定低通、One Euro、融合控制器。所有配置消费同一份事件回放，固定代码版本、参数、随机种子（若实验确需随机抽样）和设备档案。

### 4.2 核心指标

| 维度 | 指标 | 解释 |
|---|---|---|
| 平滑 | 静止段角速度 RMS、加速度与 jerk 的 p95/p99、功率谱密度 | 衡量抖动与突变；FFT 只作诊断，不把“没有高频峰”当成人体真实性证明 |
| 响应 | 输入到输出延迟 p50/p95、10%–90% 上升时间 | 防止用过度滤波换取漂亮曲线 |
| 控制 | 稳态误差、稳定时间、超调量、目标丢失后的退出时间 | 衡量收敛与降级行为 |
| 融合 | 时间残差、创新序列、通道权重、拒绝/降级次数 | 解释某次融合为何可信 |
| 任务 | 完成时间、误操作率、路径效率 | 按 Fitts 难度区间分层报告 |
| 体验 | 舒适度、可预测性、控制感的量表评分 | 由用户研究验证“自然”，不以离群检测器替代 |

PCA、Isolation Forest 可用于发现设备异常、采集错误和分布漂移，但不作为“像人”或“不可检测”的优化目标。模型训练集、参数选择集和最终用户测试分开，避免在同一批轨迹上调参与宣称通过。

### 4.3 首轮建议门槛

这些是启动实验的工程门槛，不是已验证成绩：

- 所有被融合样本时间单调，跨通道对齐残差 p95 不超过较慢通道的一个采样周期。
- 相对原始输入，静止段 RMS 至少降低 30%，同时新增端到端延迟 p95 不超过 20 ms。
- 点到点任务的超调量 p95 不高于总位移的 5%，控制输出不存在速度、加速度或 jerk 越界。
- 视觉观测过期后 100 ms 内解除其权重；用户反向输入在下一控制 tick 获得优先权。
- 同一回放与配置重复运行得到逐样本一致输出；所有阈值均能追溯到配置和实验报告。

门槛不通过时先定位时间同步、标定、估计或控制层，不通过添加随机性掩盖问题。

## 5. 四阶段交付把研究结论变成工程证据

| 阶段 | 交付物 | 退出条件 |
|---|---|---|
| R1 数据基线 | 事件 schema、统一时钟、坐标契约、设备标定工具、真实输入记录器 | 时间与坐标 fixture 全部通过，可复现一段触控+IMU 回放 |
| R2 离线算法 | 互补/Madgwick 对照、One Euro 基线、最小 jerk 轨迹器、指标脚本 | 同一回放可生成对照报告，参数与输出可追溯 |
| R3 集成原型 | 状态机、用户覆盖、目标/ROI 显式选择、降级路径、诊断 UI | 无观测或观测失效时仍保持纯用户控制，生命周期测试通过 |
| R4 用户验证 | 分层任务集、盲测方案、性能和主观报告 | 预注册指标达标；未达标项保留 FAIL，不改口径 |

首轮只推进 R1 和 R2。它们不依赖 root、不依赖真实模型，也不会扩大当前未闭环的截图和推理风险。R3 在现有检测、生命周期和帧协议门禁通过后再接入；R4 必须使用真实用户和真实设备数据。

## 6. 与当前仓库的接口边界

当前已新增独立 `motion/` 纯逻辑诊断模块；后续如实现控制建议，应继续在该边界内接收带时间戳的真实事件和用户显式选择，并只向诊断 App 或自有测试视图输出 `ViewDeltaSuggestion`。现有 `DetectResult` 需要补充 `frameId`、`captureTimeNs`、bbox 和稳定实例 ID 后，才适合参与时序跟踪。

当前 `center/ScreenCenterController` 直接按最近检测框调用 root `input swipe`，缺少时间戳、目标身份、用户覆盖、状态估计与过期保护，不属于本方案的集成基线。调研阶段保留其现状记录，但不继续优化其自动注入、轨迹拟人化或规避检测能力。

### 6.1 已实现的第一段诊断能力

`android-app/app/src/main/java/com/screen/vision/motion/` 已加入与 `center/` 隔离的纯 Kotlin 一致性分析器。它消费真实触控、真实陀螺仪与相机姿态观测，不调用 Android 输入注入 API。当前实现包含：

- 每个样本携带 `eventTimeNs`、`receiveTimeNs`、`sessionId` 与 `transformGeneration`；乱序、重复时间、跨会话、跨屏幕变换、超时和非有限数值会得到 `INDETERMINATE`，不会硬凑风险分。
- 只在相机观测的共同时间区间内累计触控和陀螺仪；触控手势按 DOWN/MOVE/UP/CANCEL 分段，避免把两次手势之间的位置跳变计为运动。
- 触控位移经设备标定转换为 yaw/pitch，陀螺仪用梯形积分转换为角位移，再与相机实际角位移计算残差和方向余弦。
- 从相机观测计算峰值角速度与峰值角加速度，输出可解释 finding、指标和 0–100 风险分；数据质量不足与行为异常是不同状态。
- `SlidingWindowConsistencyEngine` 为三个通道提供线程安全的 250 ms 有界窗口，限制单通道最大样本数；只有收到第二个独立视角观测后才生成报告。
- `MotionDiagnosticsSession` 使用 `SensorManager` 采集真实陀螺仪，并记录当前 Activity 实际收到的单指触控及历史采样点；它将 `MotionEvent` 的 uptime 时钟换算到传感器使用的 elapsed-realtime 时钟域。
- `MainActivity` 提供显式开始/停止按钮、样本计数和最新报告展示。默认像素角度比例仅用于管线诊断，正式评估前必须替换为实测标定。

这仍是窗口级诊断基线，不是线上判罚器。默认阈值只用于工程启动，必须用设备、ROM、采样率和用户群分层数据校准；单个窗口的分数不能直接用于封禁或归因。当前 App 没有独立游戏相机姿态来源，因此不会用触控或 IMU 反推数据冒充实际视角；自有渲染器或获授权遥测需要调用 `submitViewOrientation`。下一步应补角度解缠、传感器零偏处理、标定持久化及 ROC/误报率报告。
